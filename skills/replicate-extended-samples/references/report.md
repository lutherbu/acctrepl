Paths in `task.json`'s `sources` are relative to `repository`; working paths are relative to the job. Read the original records there. Edit only this job's `work/`, `draft.json`, and, for an eligible author run, `author_plan.json`. Shell command arrays in the task can be executed with Python subprocess or from a shell (quote paths). For local source metadata use bounded reads of the accepted program's named files. Never expose observation-level data.

Each row in `analyses` has a stable predecessor `scope_id` and a unique short `key`. For multiple distinct analyses in one author stage, copy its row, retain its scope_id, and assign each row a different key. Identify the original table or fit and applicable sample ID(s). Carry forward every predecessor gap. Provide a specific `reason` and `source_evidence` (file and page, line, or table) on every row. Provide actual checked data sources and vintages in the top-level `sources_checked` array of strings. List scientific time changes, path corrections, and limits in `changes` and `limitations`. Do not erase a predecessor discrepancy.

Dates use YYYY, YYYY-MM or YYYY-MM-DD on the fit's observation clock. Fill `original_begin`, `original_end`, `requested_end`, `supported_end` (verified coverage that can support estimation), and `last_added` (last actual contributing period); use null for unknown or inapplicable values. Explain contrary clock evidence. The controller checks calendar-year arithmetic. A July fiscal year uses the same fiscal convention throughout.

Choose one disposition for each analysis:

- `extended_full` or `extended_partial`: original and later observations are jointly used and a fresh native result is verified. Full requires supported coverage to the requested endpoint. Partial requires a shorter, documented attainable horizon.
- `no_added_observations`: inputs/screens or the actual fit admit no later observations. State whether established in preflight or at estimation.
- `not_applicable`: design or retained branch has no temporal observed sample to extend.
- `blocked`: missing dated data, construction route, identifiable period, software or another prerequisite. Give the exact gap.
- `prior_unexecuted`: the original fit or stage was not previously executed. Preserve its reason.
- `failed`: launched native stage failed. `unverified`: some code ran but evidence of later observations or a usable fit is insufficient.
